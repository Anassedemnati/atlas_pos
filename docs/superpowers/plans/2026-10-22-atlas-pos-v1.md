# Atlas POS v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A configurable, offline, power-cut-resilient Electron touchscreen POS for Moroccan small businesses (restaurant, café, bakery, retail), installed by a technician through a 6-step setup wizard, with multi-disk backups and a LAN web back office.

**Architecture:**
- **One Electron app, structured as clean architecture.** The main process owns the domain, use cases and all I/O: SQLite, printers, backups and the HTTP server. The renderer (till, wizard, customer display) and the LAN back office SPA call the same use cases, the renderer through a typed IPC contract and the SPA through REST.
- **Every state change is one SQLite transaction**, written as it happens. Closed tickets are immutable (enforced by DB triggers).

**Tech Stack:**
- Electron 45, electron-vite 6, Vite 7, TypeScript 5.9 (strict), React 19
- better-sqlite3 13 (N-API prebuilds for all OSes)
- Fastify 5, Zod 4, i18next, SheetJS `xlsx`, `serialport` 13, pino
- Vitest 3, Playwright (Electron), electron-builder 26
- Font: `@fontsource/ibm-plex-sans-arabic` (Latin + Arabic)

**Spec:** `docs/superpowers/specs/2026-10-22-atlas-pos-design.md` (sections referenced as §N). Mockups: `docs/mockups/01…09`.

## Global Constraints

- **Node ≥ 22.19 for tooling.** Every script that launches Electron must clear `ELECTRON_RUN_AS_NODE` (the dev shell sets it). Use `env -u ELECTRON_RUN_AS_NODE` in npm scripts via `cross-env-shell`, or a tiny `scripts/electron-env.mjs`.
- **electron-builder `npmRebuild: false`.** better-sqlite3 and serialport ship N-API prebuilds. Native `.node` files go in `asarUnpack`.
- **Money is integer centimes (`number`, safe ints).** Display is French style: `38,00 DH` and `2 450,00 DH` (narrow no-break space U+202F as the thousands separator, comma decimal, a space and `DH`). In Arabic the UI shows `271,00 درهم`.
- **Prices are entered TTC.** VAT rates are stored in basis points: 2000, 1400, 1000, 700, 0. VAT is computed per rate on the ticket (see Task 6).
- **Quantities are integer thousandths (`qtyMilli`)**: 1 item = 1000, 0,350 kg = 350.
- **IDs are UUIDv7 strings.** Ticket numbers are gap-free sequences:
  - `ticket` (no reset)
  - `credit` (`AV-000001`)
  - `invoice-YYYY` (`F-2026-00001`)
  - `order-number` (1–999, reset per business day)
- **SQLite pragmas on every connection:** `journal_mode=WAL`, `synchronous=FULL`, `foreign_keys=ON`, `busy_timeout=5000`.
- **Data dir:**
  - Windows `C:\ProgramData\AtlasPOS`
  - Linux `/var/lib/atlas-pos`, falling back to `~/.local/share/atlas-pos`
  - macOS dev `~/Library/Application Support/AtlasPOS`
  - override with env `ATLAS_DATA_DIR`
  - Layout: `db/atlas.db`, `config/installation.json`, `config/wizard-draft.json`, `backups/`, `logs/`, `prints/` (virtual printer output), `media/` (product images)
- **Languages FR, AR, EN.** UI strings live only in `src/shared/i18n/{fr,ar,en}.json`. Arabic sets `dir="rtl"`. CSS uses logical properties only (`margin-inline-start` etc.).
- **Touch:** min target 64 px at the till, 72 px for primary actions; no hover-only actions.
- **Design tokens** (§12): bg `#F4F5F7`, navy `#14213D`, teal `#0FA3A3`, amber `#F2A541`, red `#D64545`, green `#2E9E5B`, card radius 14 px.
- **Every user-visible label is i18n'd.** French is the reference copy.
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Power loss mid-write** (kill -9 while adding lines, paying, backing up). Expected: the DB opens and passes `quick_check`, every acknowledged line is present, no ticket is half-closed, and no ticket number is skipped or duplicated. **Test:** Task 8 crash harness.
2. **Backup destination missing or full** (USB unplugged, NAS offline, disk full). Expected: selling continues, the copy is queued and retried, and an amber status appears after 24 h without success. **Test:** Task 7 `pending destination` + `disk full` cases.
3. **Arabic everywhere** (RTL layout, Arabic product names, Arabic receipt on a printer with no Arabic code page). Expected: mirrored layout, French fallback for missing names, raster receipt. **Tests:** Task 13 `raster for ar`, Task 17 RTL snapshot, Task 20 e2e language switch.
4. **Money rounding with discounts and mixed VAT rates** (ticket discount spread over 20 % and 10 % lines, free items, weight items). Expected: line totals sum exactly to the ticket total, and VAT per rate adds up to TTC − HT. **Test:** Task 11 property-style tests.
5. **Wrong or hostile input on the LAN back office** (brute-force login, CSRF, a non-private client IP, a malformed CSV/XLSX import). Expected: lockout after 5 failures for 15 min, 403 on a missing CSRF token or a public IP, and import errors reported per row with nothing committed. **Tests:** Task 22 and Task 9.

**Interfaces — produces:**

- `migrate(db): { from: number; to: number }`: runs `migrations/NNN_*.sql` in order, tracked by `PRAGMA user_version`, each file in one transaction. The SQL files are bundled with Vite `?raw` imports.

  - `{ step: 0..7; startMode: 'new'|'profile'|'restore'; lang: {setup, receipt, staffDefault}; businessType; modules; catalogSource: 'template'|'import'|'empty'; importFile?: string; legal; logoPath?; vatRates; receiptHeader; receiptFooter; printers: PrinterDraft[]; routing: Record<categoryCode, printerTempId>; customerDisplay: boolean; users: {displayName, pin, profileCode, username?, password?}[]; technicianCode; backups: {role, path, label}[]; backupSchedule; autostart; kiosk; backofficePort }`
- `getDraft()` / `saveDraft(partial)` (merges and validates the step's fields)
- `applyProfileToDraft(buf)`
- `detectHardware(): { osPrinters: {name, isDefault}[]; serialPorts: {path, manufacturer}[]; deviceFiles: string[]; displays: {id, bounds}[] }`
- `testPrinter(printerDraft)`: prints `testPageDoc`
- `testBackupTarget(target)`, which also creates `AtlasBackup/.atlas-target` for USB with a new `targetKey`
- `previewImport(buf, fileName)`
- **`finishSetup(): Result<{ installationId }>`**, in this order:
  1. validate the whole draft
  2. create the DB and migrate
  3. one transaction: settings, template catalog or import or empty, rooms/tables, payment methods, profiles, users (hashed), printers + routing, backup destinations, `tech.codeHash`
  4. write `installation.json` with `setupCompletedAt`
  5. `runFull('full','setup')`
  6. `setAutostart`
  7. delete the draft
  8. return the id

  It is safe to retry: if a power cut happens before step 4 completes, the DB file is deleted and the draft remains.
- **Restore mode at Start:** `listBackupsAt(path)` and `restoreBackup`, then `installation.json` is rebuilt from the restored DB's settings.
- **Technician** (`session.isTechnician` via `verifyTechnician`):
  - `tech.applyChanges(partialDraft)` takes a `pre-change` backup first, then applies settings, modules, printers and backups
  - `tech.exportProfile()`

  - `tech.logs(tail)`
  - `tech.restore(entry)`
  - `tech.quitToDesktop()`
